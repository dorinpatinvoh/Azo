Ce qui a été fait sur l'API (azo-backend) — pour Dorin

23 octobre 2026 · migrations 20261023120000 et 20261023180000 · commit f08b0864

1. En résumé

Trois changements : le numéro du destinataire est obligatoire pour une livraison et le code de remise n'est plus visible du coursier ; le kilométrage démarre dès le départ ; la suppression de compte par l'administrateur couvre tous les profils.

Déploiement : une migration, 20261023120000_delivery_recipient_phone (colonne Delivery.recipientPhone), appliquée par render:start. Déployer le serveur avant la nouvelle application.

2. Numéro du destinataire et code de remise

  • Une commande de livraison exige le numéro du destinataire (format Bénin validé, enregistré en +229). Le champ est vide à chaque commande : rien n'est repris d'une livraison précédente.
  • Si ce numéro a un compte AZƆ̀, le destinataire reçoit son code de remise en notification (NOTIFICATION_DELIVERY_RECIPIENT_CODE, 4 langues). Sans compte, ou si c'est l'expéditeur, c'est le client qui transmet le code.
  • forCourier() masque toujours le code de remise (et le code de ramassage quand les SMS sont en service) et masque le numéro du destinataire. Le client voit ses deux codes et le numéro.

3. Kilométrage : départ

  • Le compteur est ancré sur la dernière position connue (moins de 60 s) au démarrage de la course (start) et au ramassage d'une livraison (confirmPickup) : le début du trajet n'est plus perdu ou compté trop tard.

4. Suppression de compte par l'administrateur

  • Tous les profils peuvent être supprimés : client, commercial, prestataire, agence, administrateur (y compris 0197000000).
  • Si l'effacement définitif d'un compte sans historique échoue à cause d'une donnée liée (clé étrangère), le compte est anonymisé au lieu de renvoyer une erreur.
  • Garde-fous conservés : son propre compte, le dernier administrateur actif, une course ou livraison en cours, un portefeuille non nul (« Solder et supprimer »).

4 bis. Console : nom, portefeuille, tableau de bord, remise à zéro

  • POST /admin/users/:id/name (corrige le nom du compte et du dossier prestataire, tracé dans UserProfileChange) et POST /admin/users/:id/wallet-reset (portefeuille d'un client ou prestataire remis à zéro par une écriture ; refusé pour administrateur ou agence).
  • GET /admin/stats enrichi : en cours, aujourd'hui, 7 jours (heure du Bénin), volume, retraits à payer, note moyenne ; comptes supprimés exclus.
  • Remise à zéro : table AppSetting (migration 20261023180000_app_setting, clé moneyBaselineAt, non validée sur une vraie base). POST /admin/finance/reset pose la date de départ et ramène le portefeuille administrateur à 0 ; gains, commissions, volumes, retraits, comptes, courses, livraisons, graphique et note ne comptent que ce qui suit. Rien n'est effacé en base. Un défaut de cette fonction (variable lue avant d'être déclarée : plantage du tableau de bord) a été corrigé dans f08b0864 et couvert par un test.
  • Suppression de compte : si l'effacement définitif échoue (clé étrangère), le compte est anonymisé.

5. Vérifications

  • Tests : nouvelle suite delivery-recipient (numéro invalide refusé, numéro propre à chaque commande, notification au destinataire, code masqué au coursier) ; suites kilométrage, coursier personnel et arrivée adaptées ; suppression d'utilisateur verte. tsc sans erreur.
  • Non vérifié : parcours complet sur téléphone, suppression réelle d'un compte avec données liées.
