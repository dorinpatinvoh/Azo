1. En résumé

Le parrainage : tables, routes administrateur et parrain, rattachement des prestataires à l'inscription. tsc sans erreur. Une migration (une table, deux colonnes).

Déploiement : le push de main déclenche le déploiement sur Render ; /health doit afficher 77fa4e64 ou plus récent. Le serveur doit être déployé avant l'APK.

2. Données (migration 20261018100000_referrals)

  • Table Referrer : userId (unique, le compte du parrain), code (unique, « AZO- » + 6 caractères sans I, L, O, 0, 1), active, note, createdById (administrateur), createdAt.
  • User.referrerId (clé étrangère vers Referrer, ON DELETE SET NULL, indexée) et User.referredAt : le parrain d'un prestataire. Le rôle du parrain reste CLIENT ; on le reconnaît à sa ligne Referrer (pas de nouvelle valeur de l'énumération Role).
  • Appliquée sur une base vide ; aucun écart entre le schéma et les migrations pour ces objets.

4. Calcul du suivi (referrals/referrals.module.ts, referral-logic.ts)

  • Catégorie : Speeder (DRIVER), agence, coursier personnel (COURIER + COURSIER_PERSONNEL), livreur express (autres COURIER).
  • État : dossier validé + au moins une course ou livraison terminée ces 30 jours = actif ; validé sans activité récente = inactif ; brouillon, déposé, en examen, information demandée = en attente ; refusé ; suspendu.
  • Activité : courses terminées (Ride.completedAt) et livraisons terminées (Delivery.createdAt, faute d'heure de fin). Une agence compte l'activité de sa flotte (ses chauffeurs rattachés, sans son propriétaire).
  • Recharges : transactions kind = RECHARGE et status = CONFIRMED du portefeuille du filleul (nombre, total, dernière date) ; les recharges en attente ne comptent pas.
  • Requêtes groupées (pas de requête par filleul).

  • Non vérifié : écrans sur téléphone.

6. Limites et suites possibles

  • Pas de récompense ni de commission pour les parrains : suivi seulement.
  • La liste des parrains calcule les chiffres parrain par parrain (suffisant pour quelques dizaines de parrains).
  • Le numéro d'un parrain doit être neuf : un client inscrit ou un prestataire ne peut pas le devenir.
