2. Données (migration 20261018100000_referrals)

  • Table Referrer : userId (unique, le compte du commercial), code (unique, « AZO- » + 6 caractères sans I, L, O, 0, 1), active, note, createdById (administrateur), createdAt.
  • User.referrerId (clé étrangère vers Referrer, ON DELETE SET NULL, indexée) et User.referredAt : le commercial d'un prestataire. Le rôle du commercial reste CLIENT ; on le reconnaît à sa ligne Referrer (pas de nouvelle valeur de l'énumération Role).
  • Appliquée sur une base vide ; aucun écart entre le schéma et les migrations pour ces objets.

2bis. Code promo « COM-AZO001 » et lien (commit ede1c603)

  • Referrer.code : COM-AZO + numéro d'ordre sur au moins 3 chiffres (le plus grand numéro déjà attribué + 1 ; la contrainte d'unicité protège d'une création simultanée). normalizeReferralCode accepte « com azo 1 », « comazo001 », « COM-AZO001 » ; les anciens codes AZO-XXXXXX (6 caractères sans I, L, O, 0, 1) restent acceptés.
  • Lien personnel renvoyé avec le commercial (link : création, liste, fiche, GET /referrals/me) : https://azo.angidsnpro.com/?ref=COM-AZO001#telecharger. L'adresse de base se règle par la variable d'environnement facultative REFERRAL_LINK_BASE.
  • GET /referrals/me renvoie aussi le numéro de téléphone du commercial. Les messages d'erreur parlent de « commercial ». Le nom des tables et colonnes (Referrer, referrerId) et des routes (/admin/referrals, /referrals/me) est inchangé : pas de nouvelle migration.
  • Vérifié sur une base jetable (7 vérifications) : COM-AZO001 puis COM-AZO002, numérotation qui continue après un COM-AZO007 créé à la main (COM-AZO008), lien correct, connexion du commercial, liste et fiche d'administrateur avec code et lien, rattachement avec « com azo 1 » / « comazo002 » / « COM-AZO002 », code inconnu signalé, recrue visible avec numéro masqué. 4. Calcul du suivi (referrals/referrals.module.ts, referral-logic.ts)

  • Catégorie : Speeder (DRIVER), agence, coursier personnel (COURIER + COURSIER_PERSONNEL), livreur express (autres COURIER).
  • État : dossier validé + au moins une course ou livraison terminée ces 30 jours = actif ; validé sans activité récente = inactif ; brouillon, déposé, en examen, information demandée = en attente ; refusé ; suspendu.
  • Activité : courses terminées (Ride.completedAt) et livraisons terminées (Delivery.createdAt, faute d'heure de fin). Une agence compte l'activité de sa flotte (ses chauffeurs rattachés, sans son propriétaire).
  • Recharges : transactions kind = RECHARGE et status = CONFIRMED du portefeuille du recrue (nombre, total, dernière date) ; les recharges en attente ne comptent pas.
  • Requêtes groupées (pas de requête par recrue).

6. Limites et suites possibles

  • Pas de récompense ni de commission pour les commerciaux : suivi seulement.
  • La liste des commerciaux calcule les chiffres commercial par commercial (suffisant pour quelques dizaines de commerciaux).
  • Le numéro d'un commercial doit être neuf : un client inscrit ou un prestataire ne peut pas le devenir.
