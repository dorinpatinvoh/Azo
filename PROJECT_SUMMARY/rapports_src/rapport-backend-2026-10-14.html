Rapport backend — AZƆ̀

Ce qui a changé aujourd'hui dans azo-backend — pour Dorin

14 octobre 2026 · 4 commits sur main · 23 suites / 271 tests

1. En résumé

Quatre changements côté serveur : un nouvel événement temps réel quand le client annule (le Zem est prévenu), de nouvelles pièces de dossier (photo de profil, logo) avec une migration, une liste de pièces revue pour Zem, coursier et agence, et l'interdiction de recharger AZƆ̀ Pay pour les Zem. Tout est sur main ; je n'ai pas vérifié le déploiement Render (/health doit afficher a0d08067).

À vérifier en premier : (1) la migration 20261014120000 au déploiement (§3) ; (2) l'effet de la nouvelle liste de pièces sur les comptes déjà approuvés (§4) ; (3) la règle « pas de recharge pour le rôle DRIVER » (§5), qui s'applique aussi aux chauffeurs d'agence.

2. Annulation par le client : le Zem est prévenu (rides/)

  • Nouvel événement socket ride:cancelled ({ rideId, at }), émis dans la room personnelle user:<driverId> par RidesGateway.emitRideCancelled, appelé dans RidesService.cancel quand le client annule une course qui a un chauffeur assigné (MATCHED / ARRIVED). Le chauffeur n'a donc pas besoin d'avoir rejoint la room de la course.
  • La notification push existante (NOTIFICATION_RIDE_CANCELLED_BY_CLIENT_BODY) et l'événement ride:status restent inchangés.
  • Côté Zem → client, rien de nouveau : la course repasse en PENDING (nouveau code de prise en charge) ; ride:status et la notification existaient déjà, le mobile affiche maintenant une alerte.
  • Tests : les faux gateways de rides-arrival.spec.ts et rides-offer-popup.spec.ts ont reçu emitRideCancelled. Pas de test dédié à l'événement.

3. Pièces de dossier : nouvelles valeurs et migration (providers/, Prisma)

  • Enum DocumentKind : ajout de PROFILE_PHOTO (photo de profil du Zem / conducteur / coursier) et LOGO (logo de l'agence).
  • Migration 20261014120000_document_profile_photo_logo : deux ALTER TYPE "DocumentKind" ADD VALUE IF NOT EXISTS. Appliquée par render:start (prisma migrate deploy) au déploiement. En local : npx prisma migrate deploy puis npx prisma generate (backend arrêté, sinon EPERM sous Windows). Les nouvelles valeurs ne sont utilisées dans aucune donnée de la migration, donc pas de souci de transaction avec PostgreSQL 12+.
  • Libellés (DOCUMENT_LABELS) : CNI devient « carte d'identité ou CIP » ; PROFILE_PHOTO : « photo de profil » ; LOGO : « logo de l'agence ». Ils apparaissent dans la checklist, l'admin et les messages de dossier incomplet.

  • Effet immédiat côté mobile : l'écran « Pièces » affiche la checklist renvoyée par le serveur, sans nouvelle version de l'application pour les libellés et les listes.
  • Une pièce qui n'est plus demandée pour un type est refusée à l'envoi (« La pièce … n'est pas demandée pour un dossier … »). Les fichiers déjà déposés (permis, visite technique…) restent en base et ne sont pas supprimés.
  • Comptes déjà approuvés : leur dossier n'a pas la photo de profil ou le logo. Le score KYC (kycScore, calculé sur la liste obligatoire) et les messages de pièces manquantes en tiennent compte : à surveiller dans la file admin. Aucune suspension automatique n'est déclenchée par ce changement, mais à confirmer sur les chemins d'expiration / décision (DECIDABLE_STATUSES).
  • La photo de profil est stockée comme pièce du dossier (téléchargement protégé par propriétaire). Elle n'est pas exposée aux clients : il n'existe pas de champ « photo de profil » sur User.

5. Recharge AZƆ̀ Pay interdite aux Zem (wallet/)

  • POST /wallet/recharge renvoie 403 (« Les Zem et conducteurs ne peuvent pas recharger leur compte AZƆ̀ Pay. ») quand user.role === "DRIVER". Le rôle DRIVER couvre aussi les coursiers et les chauffeurs d'agence.
  • Non touchés : le client et l'agence (recharge normale), POST /agencies/drivers/:userId/fund et /withdraw (agence ↔ chauffeur, par un autre chemin), la lecture du solde et de l'historique, le retrait Express MoMo du Zem.
  • Pas de test dédié ; le garde se trouve dans le contrôleur, avant initRecharge.
