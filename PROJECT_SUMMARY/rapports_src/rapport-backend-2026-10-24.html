Ce qui a été fait sur l'API (azo-backend) — pour Dorin

24 octobre 2026 · notifications push, accusés de commande, grille tarifaire · commit 2b7c2ab8 · aucune migration

1. En résumé

Deux changements sur les notifications : le serveur écrit désormais dans ses journaux pourquoi une notification poussée n'est pas partie, et le client reçoit un accusé de réception quand il commande une course, une course programmée ou une livraison. La grille tarifaire est remise à jour. 439 tests verts, tsc sans erreur. Aucune migration : le déploiement ne demande que le redémarrage habituel.

À savoir : je n'ai pas vu une seule notification arriver sur un téléphone. Au dernier test, un client dont le compte a été rechargé n'a rien reçu ; la cause n'est pas encore identifiée (voir §3). Aucun fournisseur de SMS n'est branché : le serveur tourne en simulation (code 0000 accepté partout) ; SMS_PROVIDER=live sans passerelle empêcherait toute connexion.

2. Accusés de commande

  • Le serveur notifiait déjà le client à presque toutes les étapes (chauffeur trouvé, proposition, arrivée, départ, fin, annulation, aucun chauffeur, livraison assignée / ramassée / livrée / annulée, recharge). Il manquait l'accusé à la commande.
  • RidesService.create : « Commande envoyée — nous cherchons un Speeder près de toi » (NOTIFICATION_RIDE_REQUESTED), ou « Course programmée enregistrée » (NOTIFICATION_RIDE_REQUESTED_SCHEDULED). DeliveryService.create : NOTIFICATION_DELIVERY_REQUESTED. Textes en 4 langues dans notification-texts.ts ; événements ride-requested et delivery-requested (l'application ne réagit qu'à ride-offered et ride-new, aucun effet de bord).
  • L'envoi est enveloppé dans un try/catch : un échec de notification ne bloque jamais une commande. Le test du destinataire de livraison a été adapté (l'expéditeur reçoit son accusé ; aucun code de remise n'est envoyé à un tiers).

3. Notifications poussées : ce qui a été trouvé

  • Le serveur envoie bien par Expo Push (NotificationsService.sendExpoPush), après une ligne dans la boîte de réception. Mais deux cas échouaient en silence : aucun jeton enregistré pour l'utilisateur, et envoi refusé par Expo (seul DeviceNotRegistered était traité).
  • Journaux ajoutés (4a1d44dc) : « Push non envoyé : aucun jeton enregistré pour l'utilisateur … » et « Expo Push API : N envoi(s) refusé(s) — <motif> » (InvalidCredentials = clé FCM absente chez Expo ; MismatchSenderId = mauvais projet Firebase). Jamais de jeton dans les journaux.
  • Côté application (voir rapport front) : google-services.json manquait, ce qui empêchait Android de créer un jeton ; il est maintenant dans l'APK. La clé FCM V1 est, d'après Sergio, déjà déposée chez Expo (non vérifiable d'ici).
  • Vérification à faire : après une commande, ouvrir les journaux Render (Logs) et chercher « Push non envoyé » ou « Expo Push API ». Résultat à communiquer.
  • Non fait : page « Notifications » dans la console pour envoyer un message à tous ou par profil (proposée).

4. SMS (information)

  • Brevo propose des SMS transactionnels par API, mais la couverture du Bénin et le prix n'ont pas pu être confirmés ; l'enregistrement d'un nom d'expéditeur (Sender ID) est obligatoire par pays depuis le 13 mars 2026. Aucun code d'envoi de SMS n'existe dans le serveur (ni Brevo, ni Twilio, ni autre). À trancher avant d'activer SMS_PROVIDER=live.

5. Grille tarifaire

  • GRILLE_TARIFAIRE_AZO.pdf du 24 octobre : courses simples (6 véhicules), colis, coursier personnel, commissions (15 % + commission téléphone 10 %, lundi au vendredi, 4 mois), retraits (prestataire : minimum 1 000 F, paiement manuel), recharges (minimum 300 F), 6 niveaux d'agence. Les tarifs n'ont pas changé ; ils viennent de tarification.json.
  • Restent « à trancher » : commission des livraisons (15 % provisoire), taux d'agence appliqué seulement aux courses simples, aucun frais d'annulation.

6. Vérifications

  • Tests : 439 verts sur 41 suites. tsc sans erreur.
  • Non vérifié : tout envoi réel de notification, la migration 20261023180000_app_setting sur une vraie base (rappel du rapport du 23), la remise à zéro du tableau de bord de la console en production.

7. Points à connaître

  • Un NPI ne peut être lié qu'à un seul compte (contrainte unique) : un compte de test qui garde un NPI bloque une nouvelle inscription avec le même NPI. Supprimer les comptes de test avant lundi.
  • Les comptes administrateur ne se connectent pas par code dans l'application tant que SMS_PROVIDER n'est pas « live » : mot de passe sur la console web.
  • Audit du 21 octobre toujours ouvert : boutique « marché » (prix négatif), SMS, suppression de compte par l'utilisateur et pages légales, schéma / migrations, dépendances vulnérables, hébergement gratuit.
